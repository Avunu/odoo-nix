# odoo-nix-tools data

Every file the `odoo-nix` commands read at run time, read through `importlib.resources`
(`PRODUCT.data_root`) so a Nix build and a `uv tool install` see the same files. The
core's own data (`core.schema.json`) comes after these: a file here shadows it.

| Path | What | Read by |
| --- | --- | --- |
| `series/<series>.json` | OCA's template for one Odoo series, verbatim (generated by `scripts/gen_series_data.py`; never edit by hand) | `series.load`, `series.effective` |
| `tool-pins.json` | odoo-nix's pins of the tools OCA leaves unpinned (`manifestoo`, `checklog-odoo`, `manifestoo-core`) and adds (`prek`, `coverage`) | `series.effective` (deviation `odoo-nix-pins`) |
| `odoo-presets.json` | a copy of `lib/odoo-presets.json` (each series' `requiresPython` and node); `tests/test_series.py` keeps them equal | `series.effective` (`odoo_python`, deviation `node-runtime`) |
| `schema/modules.schema.json` | every module's parameters and defaults, and the checkout-only keys (`shape`, `series`, `untested`) | the core's schema composition |
| `schema/fleet-entry.schema.json` | one entry of a fleet file | `odoo-nix repo …` |
| `profiles/minimal.toml`, `profiles/recommended@<minor>.toml` | the built-in profiles; frozen once released | the core's profile resolution |

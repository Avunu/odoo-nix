# odoo-nix-tools data

Every file the `odoo-nix` commands read at run time, read through `importlib.resources`
(`PRODUCT.data_root`) so a Nix build and a `uv tool install` see the same files. The
core's own data (`core.schema.json`) comes after these: a file here shadows it.

| Path | What | Read by |
| --- | --- | --- |
| `series/<series>.json` | OCA's template for one Odoo series, verbatim (generated by `scripts/gen_series_data.py`; never edit by hand) | `series.load`, `series.effective` |
| `tool-pins.json` | odoo-nix's pins of the tools OCA leaves unpinned (`manifestoo`, `checklog-odoo`, `manifestoo-core`) and adds (`prek`, `coverage`) | `series.effective` (deviation `odoo-nix-pins`) |
| `odoo-presets.json` | a copy of `lib/odoo-presets.json` (each series' `requiresPython` and node); `tests/test_series.py` keeps them equal | `series.effective` (`odoo_python`, deviation `node-runtime`) |
| `ide/vscode.json` | the VS Code data: `seed`/`seed_extensions`, what the dev shell writes into a missing `.vscode/settings.json`/`extensions.json` (`modules/devenv.nix` reads this file), and `managed`, the `ide` module's jsonc-merge spec, which repeats no seeded leaf | `context.ide_data` (`templates/ide/*.json.j2`), `modules/devenv.nix` |
| `schema/modules.schema.json` | every module's parameters and defaults, and the checkout-only keys (`shape`, `series`, `untested`) | the core's schema composition |
| `schema/fleet-entry.schema.json` | one entry of a fleet file | `odoo-nix repo …` |
| `schema/gate-report.schema.json` | the report `odoo-nix gate lint\|test` writes (`.odoo-nix/gate/<gate>.json`) | `commands/gate.py`, `tests/test_gate.py` |
| `profiles/minimal.toml`, `profiles/recommended@<minor>.toml` | the built-in profiles; frozen once released (`tests/test_profiles.py` `FROZEN` records each file's digest: a changed `recommended` is a new `recommended@<minor>.toml`) | the core's profile resolution |
| `manifest.d/<nn>-<area>.json` | the managed files: one entry per file (strategy, module, template, local regions), the retire rules | the core's manifest (`scaffold.manifest`) |
| `templates/` | the managed files' templates; the generated bodies come from `context.Gen` (`.ruff.toml`, `.pylintrc*`, the pre-commit hooks and exclude, the eslint and prettier configs) | the core's renderer |
| `fixtures/<name>.json` | the fixture checkouts `profile validate` and the conformance check sync (path → text, with the `example-org` locks); generated by `scripts/gen_fixture_data.py` from `tests/fixtures/standards-<name>`, never edit by hand | `fixtures.FIXTURES` |
